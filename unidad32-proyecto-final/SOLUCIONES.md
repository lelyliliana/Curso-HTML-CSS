# Comparar tu proyecto con la referencia

[Proyecto y requisitos](PRACTICA.md) · [Lección](README.md) · [Índice](../README.md)

La [biblioteca del barrio](../ejemplos/sitio-final/README.md) ofrece una implementación completa para consultar estructura, CSS y comportamientos. Su solución se explica también en [el taller](../unidad31-taller/SOLUCIONES.md). No hay una única apariencia correcta.

## Relación entre requisitos y archivos

| Requisito | Implementación de referencia |
|---|---|
| Conocer propósito | Hero y recursos de index.html |
| Llegar a actividades | Enlaces a fragmentos de talleres.html |
| Leer horario | caption, th/scope y región de tabla |
| Comprender preguntas | details/summary con texto completo |
| Practicar contacto | Labels, radios, ayudas y validación de contacto.html |
| Evitar prometer envío | Aviso de contacto y explicación de resultado.html |
| Adaptarse | Wrapping, Grid fluido y una query de portada |
| Mantener consistencia | Tokens, tarjeta y variante en styles.css |
| Navegar con teclado | HTML nativo, salto, foco y orden DOM |

## Límites

La referencia no tiene base de datos, autenticación ni servicio de correo. Un sitio publicado sigue siendo estático. Los recursos de ejemplo son pequeños y no demuestran por sí solos una optimización de fotografías reales. El rendimiento de tu publicación debe medirse bajo sus condiciones, no copiarse de otra ejecución.

## Autorrevisión

Compara comportamientos, no solo capturas. Un proyecto con otra paleta puede cumplir mejor si tiene contenido más claro y acceso consistente. Para cada diferencia, pregunta qué necesidad resuelve y qué evidencia la respalda.
