# Unidad 32 — Proyecto final

[Volver al índice del curso](../README.md) · [Ver el curso en Aprende con Leli](https://lelyliliana.github.io/aprende-con-leli/cursos/html-css/)

## Propósito

Construir y publicar un sitio que pueda comprenderse, adaptarse, navegarse y mantenerse.

La apariencia es solo una dimensión.

# Etapa 1 — Propósito

Define:
- audiencia;
- objetivo;
- contenido;
- páginas/secciones;
- acción principal.

No empieces por colores.

# Etapa 2 — Arquitectura de contenido

Crea esquema:
```text
Inicio
├── propuesta
├── proyectos
└── contacto
```

Define navegación y jerarquía de headings.

# Etapa 3 — Wireframe

Dibuja distribución sin detalles visuales.

Decide qué cambia por espacio y qué permanece.

# Etapa 4 — HTML semántico

Implementa:
- lang;
- title;
- landmarks;
- headings;
- enlaces;
- imágenes;
- tablas/formularios cuando realmente apliquen.

Debe ser comprensible sin CSS.

# Etapa 5 — Accesibilidad base

Comprueba:
- teclado;
- foco;
- alt;
- labels;
- nombres;
- orden DOM;
- color no único.

# Etapa 6 — Sistema visual

Define tokens:
- color;
- espacio;
- tipografía;
- radios;
- superficies.

Evita valores arbitrarios repetidos.

# Etapa 7 — Layout

Usa flujo, Flex y Grid según relación espacial.

No se exige usar ambos si el proyecto no los necesita.

# Etapa 8 — Responsive

Primero técnicas fluidas.

Añade media/container queries solo en puntos donde el contenido necesite cambio.

Prueba un continuo de tamaños.

# Etapa 9 — Imágenes

Define:
- alt;
- dimensiones;
- formato;
- srcset/picture cuando aporte;
- estrategia de carga.

# Etapa 10 — Estados

Incluye:
- hover cuando aplique;
- focus-visible;
- active/selected;
- disabled/error si existen.

No dependas solo de color.

# Etapa 11 — Movimiento

Solo si aporta.

Respeta reduced motion.

# Etapa 12 — Metadatos

Por página:
- title;
- description;
- OG cuando aplique;
- canonical únicamente si conoces la URL pública correcta.

# Etapa 13 — Calidad

Usa:
- DevTools;
- validación;
- teclado;
- zoom 200%;
- responsive;
- inspector de accesibilidad.

Registra y corrige problemas.

# Etapa 14 — Rendimiento

Mide baseline.

Optimiza al menos un recurso real y vuelve a medir.

No se exige una puntuación perfecta.

# Etapa 15 — Publicación

Publica en hosting estático.

Audita **la URL pública**, no solo localhost.

Comprueba HTTPS, rutas y recursos.

# Etapa 16 — README

Debe explicar:
1. propósito;
2. estructura;
3. cómo ejecutar localmente;
4. URL pública;
5. decisiones de diseño;
6. accesibilidad;
7. optimizaciones.

# Etapa 17 — Revisión final

Usa `PLANTILLA_PROYECTO.md`, `RUBRICA.md` y `CHECKLIST.md`.

Pregunta:
- ¿se entiende sin CSS?
- ¿funciona con teclado?
- ¿soporta zoom?
- ¿hay scroll horizontal accidental?
- ¿los componentes son reutilizables?
- ¿las imágenes son apropiadas?
- ¿hay recursos rotos?
- ¿otra persona puede mantenerlo?

# Entregables

- código HTML/CSS;
- recursos optimizados;
- README;
- URL pública;
- evidencia de validación/accesibilidad;
- medición antes/después.

# Cierre

> Un buen sitio no es el que solo se ve bien en una captura: es el que conserva estructura, legibilidad, adaptación, accesibilidad y rendimiento cuando cambia el usuario, el dispositivo y el contenido.
